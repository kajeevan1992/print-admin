V180 - Real tenant DB wiring for internal catalog read/write

Scope kept to backend/core only. No UI pages, no public API routes, and no proxy routes were added.

Changed:
- Added src/core/catalog/internal-catalog-http.ts as a shared internal route handler for existing internal catalog endpoints.
- Existing internal catalog endpoints now support GET, POST, PUT, PATCH, and DELETE:
  - /api/internal/catalog/products
  - /api/internal/catalog/categories
  - /api/internal/catalog/collections
  - /api/internal/catalog/tags
  - /api/internal/catalog/materials
  - /api/internal/catalog/finishes
  - /api/internal/catalog/option-sets
- Catalog reads resolve the configured tenant/site database connection and read from tenant Postgres tables.
- Product/category writes persist to first-class Product and Category tables.
- Collections/tags/materials/finishes/option-sets persist to CoreCatalogRecord.
- Writes call ensureTenantSchema before writing, then ensure a Tenant row exists so FK-backed Product/Category inserts work on new tenant databases.
- Deletes are scoped by tenantId and resource.

Important behaviour:
- Writes require a configured tenant DB and return a clear internal-core error if none is available.
- Reads still fall back to demo catalog rows only when no tenant DB is available/uninitialised, so admin status screens do not hard crash before DB setup.
- Public /api/v1 catalog routes were not expanded; public API remains external-read focused.

Validation note:
- Full npm build could not be run in this environment because node_modules are not present and dependency install timed out. The code changes are limited TypeScript route/core changes and should build once dependencies install in the deploy environment.
