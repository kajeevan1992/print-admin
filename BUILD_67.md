## What Build 67 adds

### Safe launch test order generator service

Added:

- `src/core/launch/launch-test-order-generator.service.ts`

The service can:

- preview a test order payload without creating anything
- create a clearly marked test order through existing `saveOrder()`
- verify VAT summary after the order is saved
- generate a collection pass using Build 61
- run ready collection automation using Build 64
- queue collection-ready notification using Build 62 when required
- list recent launch test orders

### Test order marker

Generated orders use:

- order number prefix: `TEST-HOLO-`
- note: `BUILD 67 TEST DATA — safe launch test order. Do not produce or invoice.`
- internal notes:
  - `BUILD 67 TEST DATA`
  - `Generated by Launch Test Order Generator`
  - `Do not produce`
  - `Do not invoice`
- marker: `BUILD_67_SAFE_TEST_ORDER`

### Test order contents

The generated order includes:

- Business Cards test line — standard VAT
- A5 Flyers / Leaflets test line — zero VAT
- Design Service test line — standard VAT even if base print is zero-rated
- collection fulfilment for Sidcup by default
- test payment status only

This verifies mixed VAT behaviour and collection fulfilment in one controlled order.

### API

Preview/list API:

```txt
GET /api/internal/launch/test-order
GET /api/internal/launch/test-order?list=true
```

Active creation API:

```txt
POST /api/internal/launch/test-order/run
```

Creation requires exact confirmation:

```json
{
  "confirm": "CREATE_TEST_ORDER"
}
```

Optional POST fields:

```json
{
  "status": "QUALITY_CHECK",
  "productSlug": "business-cards",
  "locationSlug": "sidcup",
  "customerEmail": "launch-test@holoprint.co.uk",
  "customerName": "Launch Test Customer",
  "generatePass": true,
  "runAutomation": true,
  "queueNotification": true
}
```

## Important safety behaviour

If `runAutomation` is enabled, it queues via the existing queue/send separation. Emails still require Build 63 email sender controls or explicit send settings.
