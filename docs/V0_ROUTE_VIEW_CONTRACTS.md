# v0 Route View Contracts

## Purpose

A v0 theme can now own the visual layout for these storefront routes:

- category and all-products pages
- product pages
- quote request pages
- basket pages
- checkout success and cancellation pages

The SaaS remains authoritative for tenant resolution, published products, product configuration, dependencies, pricing, VAT, quote submission, checkout and orders.

## Safe props

Route components receive presentation-ready values from `src/v0-themes/contracts.ts`, including:

- brand colours and logo
- safe navigation links
- product/category titles, images and descriptions
- formatted display prices
- selected option labels
- quantity and turnaround summaries
- order status and reference text

They do not receive Prisma records, API credentials, pricing rows, VAT resolvers, tenant IDs or Stripe sessions.

## Protected slots

Interactive authority remains inside internal server/client components and is passed to the theme as a React slot:

- `ProductPage.slots.purchase` — quote action or live product configurator
- `QuotePage.slots.form` — tenant-bound quote submission form
- `CartPage.slots.checkout` — internal checkout form and price verification

The v0 package decides where these slots appear but cannot access their internal services.

## Canvas proof

`src/v0-themes/canvas/RouteViews.tsx` implements all route contracts. Canvas now presents a consistent theme across homepage, categories, products, quotes, basket and checkout status while continuing to use the original SaaS controllers.

## New themes

The starter generated by `pnpm theme:create` includes `RouteViews.tsx`. After design approval, the reviewed runtime adapter supplies its route views to `renderV0ThemePackage`.

## Remaining refinement

The configurator and checkout widgets are intentionally protected internal slots. A later visual refinement can split those widgets into controlled view props and callback adapters, but pricing and checkout authority must remain outside v0 packages.
